# Пользователи и права Barnix

Установщик отдельно запрашивает имя и пароль обычного пользователя, затем пароль
root с подтверждением. На чистом LiveCD эти вопросы задаются при первом запуске.
Заводского пароля нет. Вход обязателен. Изменения LiveCD остаются в RAM.

Каждый пользователь получает `/home/USERNAME/useretc`. По умолчанию ему доступны
все операции внутри собственного home и запуск программ в `/bin`. Чужие home,
корень и системные каталоги недоступны для изменения. `/etc` всегда доступен
только root: даже chmod с паролем не позволяет делегировать файл учётных записей.
Root обходит проверки файловых прав. Перед изменением таблицы разделов нужно
размонтировать все разделы соответствующего диска.

## Команды

```
whoami
su                   # пароль root; новый вложенный сеанс
su alice             # пароль alice; root может переключиться без пароля
exit                 # возврат из su; без вложенного сеанса — новый вход
logout               # новый вход
sudo write /etc/test hello  # пароль root, права только на время команды
useradd bob          # root: имя + скрытый ввод и подтверждение пароля
chmod alice=x file=/bin/cat
chmod alice=r passwd=unlock file=/home/alice/report
```

`chmod USER=RIGHTS [passwd=PASSWORD] file=PATH` принимает любую перестановку
`r`, `w`, `x`; пустое `USER=` отзывает права. За один вызов меняется одна запись.
Права каталога наследуются; более конкретная запись имеет приоритет. Пути
нормализуются, поэтому `..`, повторные `/` и относительные пути не обходят правила.

Root задаёт пароль защиты прав параметром `passwd`. Обычный пользователь с этим
паролем может изменить права защищённого файла; пароль не нужен для обычного
чтения или записи, которые проверяют ACL. В своём home можно менять незащищённые
права без пароля. Без `passwd` существующая защита сохраняется. Метаданные находятся
в `/etc/access.cfg`; старые `.perms` больше не используются. Имена учётных записей:
до 23 символов, `a-z`, `0-9`, `_`, `-`; пароли — до 63 символов.

Новые пароли записываются как `$bx1$` с солью и 4096 раундами SHA-256, не открытым
текстом. Старые записи `имя:пароль` читаются для совместимости. Это собственный
формат учебной ОС, не Linux shadow/PAM и не memory-hard KDF. Повреждённый файл
учётных записей не создаёт автоматический вход root.

`su`, `sudo`, `useradd`, `exit`, `logout` — команды сеанса bssh. Конвейеры и
редиректы поддерживают Linux ELF; сеансовые команды запускаются отдельно.
`sudo` здесь использует пароль **root**, без sudoers и кэша авторизации.

## Настройки и игры

```
theme bios
write /home/alice/useretc/sys-lang.cfg LANG=ru
init
snake
pong                 # один игрок против компьютера
pong 2               # два игрока
paint                # мышь, пиксельный рисунок, /home/USER/picture.bmp
```

Тема применяется сразу, сохраняется в `useretc/theme.cfg` и восстанавливается при
входе/переключении пользователя. Темы: default, dark, light, solarized, monokai,
dracula, nord, bios, pink-panther, green, random. Язык хранится отдельно для каждого
пользователя в `useretc/sys-lang.cfg` (`LANG=en` или `LANG=ru`).

Snake: стрелки/WASD. Pong: W/S или стрелки в одиночном режиме; W/S слева и стрелки
справа в режиме двух игроков. P — пауза, Q/Esc — выход. Скорость задаёт PIT,
поэтому игры не требуют нажатий для продвижения и не зависят от пустого CPU-цикла.

## Граница изоляции

Linux ELF работает в ring 3 и использует проверяемые файловые системные вызовы.
Старый нативный Barnix ABI работает в ring 0: это доверенные расширения ядра.
Обычный пользователь может запускать такие программы только из `/bin`, куда их
устанавливает root; пользовательские программы должны использовать Linux ELF.
Root не должен предоставлять запись в доверенные нативные программы.

## Проверка

`make test-permissions` — проверки VFS, паролей, ACL и планировщика разделов.
`make test-system-permissions` — установка/загрузка BIOS и UEFI, сохранность
существующего раздела, ручная разметка, вход, su/sudo, настройки и обе игры в QEMU.
