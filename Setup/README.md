# Barnix Setup / distro builder

Два установочных LiveCD на базе Barnix, в корне репозитория:

- [`barnix-legacy-setup.iso`](../barnix-legacy-setup.iso) — Legacy BIOS.
- [`barnix-efi-setup.iso`](../barnix-efi-setup.iso) — **UEFI x64**, Secure Boot выключен.

Каждый ISO имеет загрузочную запись только своей платформы. Ядро и программы
Barnix остаются 32-битными; EFI GRUB передаёт управление в protected mode.
UEFI-версия выводит мастер и оболочку через GOP framebuffer, включая кириллицу,
цвета и курсор. Поддерживается RGB framebuffer 24/32 бит ниже 4 ГиБ.
Для ввода используются PS/2-клавиатура и мышь либо USB HID boot-мышь на прямом порту UHCI. Пункты мастера и кнопки
«Вверх», «Вниз», «Назад», «Далее» доступны мышью; текст вводится клавиатурой.

## Сборка и запуск

Из корня репозитория:

```sh
make setup                       # собрать оба ISO
make run-setup                   # Legacy BIOS
make run-setup FIRMWARE=efi      # UEFI / OVMF: установка
make run-installed FIRMWARE=efi  # загрузить установленный target-efi.img без ISO
make run FIRMWARE=efi            # тот же запуск установленной EFI-системы
make test-setup                  # проверка Legacy
make test-setup-efi              # проверка UEFI и загрузки без CD
```

Или `make -C Setup`, `make -C Setup run`, `make -C Setup test`.

Legacy запускается с отдельным `Setup/target.img` на 5 ГиБ + 1 МиБ.
UEFI использует `Setup/target-efi.img` на 5 ГиБ + 65 МиБ.
OVMF хранит переменные в отдельном `Setup/OVMF_VARS.fd`.
Файл создаётся только при отсутствии; повторный запуск сохраняет его содержимое.
Основной `barnix-ext2.img` автоматически не подключается.
`make run-installed` загружает `Setup/target.img` в Legacy, а с `FIRMWARE=efi` —
`Setup/target-efi.img` в OVMF. Этот режим не подключает установочный CD,
не требует сборки ISO и не создаёт отсутствующий диск. Обычный `make run`
без `FIRMWARE=efi` сохраняет прежний режим LiveCD с `barnix-ext2.img`.
Перед запуском скрипт печатает абсолютные пути подключённых целевых образов.

Чтобы установка и последующая загрузка использовали свой образ:

```sh
make run-setup FIRMWARE=efi SETUP_DISK=disks/system.img
make run-installed FIRMWARE=efi SETUP_DISK=disks/system.img
```

`SETUP_DISK` должен указывать на существующий образ; задавайте одинаковый путь
при обоих запусках. Прямой эквивалент загрузки установленной системы:
`python3 Setup/run.py --installed --firmware efi --disk disks/system.img`.

Указать свои существующие образы можно так:

```sh
python3 Setup/run.py --disk disks/system.img --disk disks/other.img
python3 Setup/run.py --firmware efi --transport nvme --disk disks/system.img
```

По умолчанию первые три образа подключаются через IDE, следующие восемь —
через VirtIO; четвёртый IDE-слот занят CD. `--transport sata|nvme|virtio`
выбирает контроллер для всех образов (до 6 SATA или 8 NVMe/VirtIO).
Мастер использует общий список IDE, USB/UHCI, SATA/AHCI, NVMe и VirtIO.
Длинный список прокручивается стрелками по шесть строк.

Сборка использует GCC с поддержкой i386, binutils, Python 3, e2fsprogs,
GRUB с модулями **i386-pc и x86_64-efi**, `grub-mkrescue`, xorriso,
**dosfstools и mtools**. Для запуска/тестов нужны QEMU и **OVMF x64**.
Пути OVMF можно указать через `--ovmf-code` и `--ovmf-vars` в `Setup/run.py`.
По умолчанию используются `/usr/share/edk2/x64/OVMF_CODE.4m.fd` и
`/usr/share/edk2/x64/OVMF_VARS.4m.fd`. Образы собираются без loop-устройств, монтирования и доступа к дискам хоста.

## Мастер

1. Приветствие и выбор English / Русский. `Esc` открывает оболочку LiveCD.
2. Выбор физического диска с размером и проверкой минимальной ёмкости.
   `R` повторяет поиск; RAM-диск и CD не предлагаются как назначения.
3. Автостирание, автодобавление разделов или полностью ручная MBR-разметка.
4. Выбор состава: Minimal, Standard или Complete; имя компьютера и язык.
5. Имя пользователя, его пароль и отдельно пароль root, с подтверждением.
6. Сводка. Для запуска записи нужно ввести точное имя выбранного диска.
7. Форматирование, перенос файлов из шаблона с проверкой, настройки, запись MBR.
8. Экран результата: перезагрузка либо возврат в LiveCD.

До подтверждения нет записи на диски. `Esc` возвращает на предыдущий шаг.
После начала записи отмена отключена. При ошибке мастер показывает её и
позволяет повторить установку; резервная копия старой системы не создаётся.

Имя и параметры сохраняются в `/etc/hostname`, `/etc/sys-lang.cfg`,
`/etc/install.cfg`. Имя компьютера пока является настройкой, а не именем DNS:
сетевой стек Barnix не использует его для сетевого обнаружения.

## Варианты дистрибутива

Состав задаётся в [`profiles.json`](profiles.json):

| Вариант | Содержимое |
| --- | --- |
| Minimal | Ядро, оболочка, операции с файлами/дисками, настройка системы |
| Standard | Minimal + сеть, загрузки, git, макросы, panic |
| Complete | Standard + примеры ELF, Snake, Pong и Paint |

Поле `distribution` меняет название в шапке мастера. У каждого варианта есть
`id`, `title`, `description`, список `commands` из `apps/bin`, необязательные
`examples` из `apps` и `extends` для наследования ранее объявленного варианта.
Добавьте программу в сборку приложений Barnix, затем в нужный список.

В текущей версии мастер ожидает ровно три варианта. После изменения JSON
выполните `make setup`: подписи, состав файлов и образы пересоберутся.
Компактные шаблоны с 2 МиБ ext2 находятся в `Setup/build/{legacy,efi}-{id}.img`.
Установщик переносит из них файлы и права доступа в новый раздел нужного размера.
Сборка каждого варианта проверяется `e2fsck`.

## Разметка и загрузка

Оба варианта используют MBR. Автодобавление сохраняет существующие разделы и
выделяет новые в свободных промежутках. Ручной редактор позволяет выбрать
расположение, размер и слоты root/ESP. GPT и расширенные разделы не поддерживаются.
Подробности и команды: [разметка диска](../PARTITIONING.md). Таблица ниже описывает
расположение по умолчанию при автостирании, а не ограничение ручного режима.

| Вариант | Загрузочная область | Системный раздел | Минимум |
| --- | --- | --- | --- |
| Legacy | MBR GRUB + область до 1 МиБ | ext2 от 1 МиБ, до 5 ГиБ | 3 МиБ |
| UEFI | FAT32 ESP 64 МиБ от 1 МиБ, тип MBR `0xEF` | ext2 от 65 МиБ, до 5 ГиБ | 67 МиБ |

Размер ext2 — `min(диск − загрузочная область, 5 ГиБ)`; очень маленькая последняя
группа блоков может быть отброшена. Ядро и конфигурация GRUB находятся в `/boot`.
EFI-установщик записывает стандартный путь `EFI/BOOT/BOOTX64.EFI`; он не зависит
от созданной установщиком записи NVRAM. После переноса диска UEFI GRUB находит
ext2 на том же устройстве, с которого был запущен.

При автостирании установщик сначала убирает загрузочный сектор. Новый MBR публикуется
после копирования, проверки и сохранения настроек. Сбой до завершения может
оставить диск незагрузочным: запустите мастер повторно с LiveCD.

После установки извлеките CD и выберите установленный диск в соответствующем режиме BIOS или UEFI.
`run.py` загружает CD один раз; следующие загрузки идут с HDD. Если выбран
не первый диск, используйте загрузочное меню QEMU (Esc).

GRUB передаёт UUID своего раздела ядру; Barnix ищет этот UUID среди всех поддерживаемых дисков.
Поэтому перенос диска между IDE-слотами не заставляет ядро открыть другой root.
Установленная система не нуждается в LiveCD.

Сборщик размещает готовые компоненты GRUB в обычном файле образа по формату
[i386-pc boot.h](https://raw.githubusercontent.com/rhboot/grub2/master/include/grub/i386/pc/boot.h)
и [diskboot.S](https://raw.githubusercontent.com/rhboot/grub2/master/grub-core/boot/i386/pc/diskboot.S).
Адреса загрузочных блоков задаются аналогично
[GRUB setup.c](https://raw.githubusercontent.com/rhboot/grub2/master/util/setup.c).
Это отдельный путь для фиксированной разметки образов, а не универсальная
замена `grub-install` для физических дисков хоста.

## Проверки

`make test-setup` проверяет настоящий мастер через клавиатуру QEMU:

- слишком маленький диск, переходы назад, неверное подтверждение и отмену;
- установку на второй диск без изменения первого;
- настройки, выбранные компоненты и целостность ext2;
- запуск без CD и перенос между IDE-слотами;
- запись файлов и их сохранение после перезагрузки;
- минимальный вариант с русским языком.

Снимок экрана результата сохраняется в `Setup/build/finished.ppm`.
Обычные проверки LiveCD: `make test-shell`.

`make test-setup-storage` проверяет установку и загрузку без CD через AHCI,
NVMe и VirtIO. На виртуальном диске 8 ГиБ создаётся том 5 ГиБ, проверяется
сохранность данных за его пределами и отсутствие ошибок `e2fsck`.
Ограничения отдельных драйверов перечислены в основном README.

`make test-setup-efi` запускает настоящий мастер через OVMF, устанавливает систему
на второй диск и проверяет FAT32/ext2. Затем без ISO и с чистыми переменными
OVMF проверяет загрузку через IDE, NVMe, VirtIO и SATA, исполнение программ,
сохранение файлов и неизменность другого диска. Снимки экрана:
`Setup/build/efi-welcome.ppm`, `efi-finished.ppm`, `efi-shell.ppm`.

Framebuffer получает параметры через [Multiboot v1](https://raw.githubusercontent.com/rhboot/grub2/master/include/multiboot.h).
Драйверы сохраняют общие ограничения Barnix, перечисленные в основном README.

## Добавление своего ELF в Complete

```sh
make add_elf /path/to/myapp.elf
make setup
```

Первая команда сохраняет ELF в `Setup/extra-apps/` и сразу добавляет его в
`/bin/myapp.elf` и `/myapp.elf` всех образов `disks/*.img`, включая
`WINDAGOVNO.img`. Вторая пересобирает установочные ISO: программа включается
только в **Complete**. Исходный файл после импорта можно переместить или удалить.
Повторный импорт обновляет программу. Для пути с пробелами используйте
`make add_elf ELF="/path with spaces/myapp.elf"`. Перед импортом остановите QEMU;
данные дисков проверяются на временных копиях. Поддержаны ext2 без разделов и
MBR с одним основным Linux-разделом. Если дисков нет, ELF только регистрируется
для Complete. `make clean` сохранённые ELF не удаляет.
